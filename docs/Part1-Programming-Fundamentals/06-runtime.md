# 第 06 章 · 运行时

**简体中文** ｜ [English](./06-runtime.en-US.md)

---

> 前几章讲清了：源码怎么被编译或解释、字节码怎么在虚拟机里执行。但程序真正"跑起来"时，语言还在背后默默替你做很多事——分配和回收内存、抛异常、调度线程、把热点代码即时编成机器码。这一整套支持，就叫**运行时（Runtime）**。这一章，我们给 Part 1 的"翻译 / 执行"链收尾。

## 1. 学习目标

本章结束后，你将能够：

- 分清"运行时"的两个含义：**运行期（run time，与编译期相对）** 与 **运行时系统 / 运行时库（runtime system）**；本章主要讲后者；
- 列出运行时系统的典型服务：内存管理（GC）、异常处理、线程 / 调度、类型信息 / 反射、JIT；
- 说清 **JIT** 的核心思想：运行时把"热点"字节码即时编成机器码，兼得解释的"启动快"与编译的"运行快"；
- 理解"运行时开销"从哪来，以及为什么 C++ 的运行时最"薄"、托管语言的运行时最"厚"；
- 把第 02–05 章的翻译 / 执行链，在这里收成一张完整的图。

---

## 2. 为什么会出现（核心问题）

> **核心问题：源码翻译好了、字节码也有虚拟机执行了，为什么程序跑起来还需要一大套"看不见的"支持？这套支持是什么、由谁提供？**

因为高级语言把很多脏活累活——内存回收、越界检查、异常展开、线程调度、动态类型信息——统统交给一个**运行时系统**代管，好让你专注业务逻辑。代价是：这套系统本身要占内存、花 CPU，这就是"**运行时开销**"。而 **JIT** 的出现，正是为了把"解释执行慢"这一项开销补回来。

---

## 3. 历史脉络

- **早期 · C 也有运行时**：C 运行时库（CRT）负责程序启动（从 `_start` 到 `main`）、`malloc/free`、标准库函数。只是它非常"薄"——几乎不替你做额外的事。
- **1990s–2000s · 托管运行时兴起**：JVM（1995）、CLR（2000s）带来"厚"运行时——内置 GC、异常、线程、安全、类加载。
- **JIT 的谱系**：Self 语言（1980s–90s）开创了自适应优化；HotSpot JVM（1999）把"热点探测 + JIT"做成主流；V8（2008）用 JIT 让 JavaScript 快到能撑起现代 Web 应用。
- **2009 · Go 运行时**：内置 goroutine 调度器与 GC，但程序**编成原生机器码**，运行时是**链接进可执行文件的一段代码**，而非独立虚拟机——这说明"运行时"并不等于"虚拟机"。

```mermaid
flowchart LR
    CRT["C 运行时库<br/>薄"] --> JVM["JVM / CLR<br/>1995–2000s · 厚（GC/异常/线程）"]
    JVM --> JIT["HotSpot 1999 · V8 2008<br/>热点探测 + JIT"]
    JIT --> GO["Go 运行时 2009<br/>原生码 + 内置调度/GC"]
```

## 4. 它到底是什么 · 底层主线

**运行时（运行时系统）＝ 你的程序运行时，语言 / 平台在背后提供的一整套支持代码与服务。** 它的形态可以不同：可能是一个虚拟机（JVM、CLR），可能是链接进可执行文件的一段库（C 的 CRT、Go 的 runtime），也可能是引擎的一部分（V8）。

它通常提供这样一份服务清单：

- **内存管理**：分配 + 自动回收（GC）——第 35 章细讲；
- **异常处理**：栈展开、寻找匹配的 `catch`；
- **并发调度**：线程 / 协程的调度与同步——Part 6；
- **类型信息与反射**：运行时仍知道对象是什么类型——第 29 章；
- **JIT 编译**：把热点字节码即时编成机器码。

其中 **JIT（Just-In-Time，即时编译）** 是本章重点。它的思路是"边跑边编"：

```mermaid
flowchart LR
    BC["字节码"] --> INT["解释执行<br/>（启动快）"]
    INT --> MON["运行时监测<br/>找出热点代码"]
    MON --> JITC["JIT：热点编成机器码"]
    JITC --> FAST["后续直接跑机器码<br/>（接近原生）"]
```

把三种执行方式放在一起看，定位就清楚了：

- **AOT（提前编译）**：运行前全部编成机器码，启动即快——但编译时**看不到运行时信息**。
- **解释**：即时、灵活，但逐条翻译**慢**。
- **JIT**：折中且更聪明——先解释着跑起来，运行时收集信息（哪些代码热、变量常是什么类型），再把热点编成机器码，甚至据此做**投机优化**（假设类型稳定；一旦假设被打破，就"去优化"退回解释）。

由此形成一条"运行时厚薄"的谱系：

- **最薄**：C / C++（几乎只有 CRT，其余你自己管）——开销低、可预测、贴近机器；
- **居中**：Go / Rust（有少量运行时或调度，但编成原生码）；
- **最厚**：Java / C# / Python / JavaScript（完整托管运行时：GC + 异常 + 反射 + JIT）——省心、安全，但开销更大。

至此，第 02–05 章的链条终于闭合：**源代码 → 编译 / 解释 → 字节码 → 虚拟机 → 运行时**——这就是一段代码从"文本"到"在机器上产生效果"的完整旅程。

> ⚠️ **注意："运行时"这个词有两个意思，别混。**
> - **运行期（run time）**：一个**时间段**，与"编译期（compile time）"相对——指程序正在运行的那段时间（如"这个错误在运行期才暴露"）。
> - **运行时系统 / 运行时库（runtime system）**：一堆**代码与服务**，在运行期支撑你的程序（如 JRE、.NET runtime、Go runtime）。
>
> 本章讲的主要是后者。中文都叫"运行时"，英文也都用 runtime，靠上下文区分。

## 5. 关键概念与术语

- **运行期（run time）**：程序运行的时间段，与编译期相对。
- **运行时系统 / 运行时库（runtime system）**：运行期支撑程序的代码与服务（CRT、JRE、.NET runtime、Go runtime）。
- **JIT（即时编译）**：运行时把热点字节码编成机器码。
- **热点（hot spot）**：被频繁执行的代码。
- **投机优化 / 去优化（speculative optimization / deoptimization）**：基于运行时假设做激进优化，假设失效时退回。
- **AOT vs JIT vs 解释**：三种翻译 / 执行时机。
- **托管运行时 / 运行时开销**：运行时提供的服务，及其占用的内存与 CPU。

## 6. 在本书六门语言中的体现

| 语言 | 运行时形态 | 执行加速 | 运行时"厚薄" |
|------|-----------|---------|-------------|
| JavaScript | JS 引擎（如 V8）内置运行时 | JIT（TurboFan） | 厚 |
| Python | CPython 运行时 | 传统无 JIT（PyPy 有；CPython 3.13 起加实验性 JIT） | 厚 |
| Java | JVM / JRE | JIT（HotSpot C1 / C2） | 厚 |
| C++ | C 运行时库（CRT）+ 你自己 | 无（AOT 原生码） | 薄 |
| C# | CLR / .NET 运行时 | JIT（并提供 AOT 选项） | 厚 |
| SQL | 数据库引擎运行时 | 执行计划缓存等 | —（专用） |

这张表其实回答了很多"为什么"：

- **C++ 为什么快**：运行时最薄，没有 GC、没有 JIT 停顿，直接跑原生码——代价是内存要你自己管。
- **Java 为什么"启动略慢、跑久了却很快"**：启动要拉起 JVM + 先解释，但热点被 JIT 编成机器码后，长时间运行可接近 C++。
- **Python 为什么在纯 CPU 密集时偏慢**：CPython 传统上没有 JIT，一直在解释字节码（这也是 PyPy 和 3.13 实验性 JIT 想解决的）。

## 7. 常见误解

- **"运行时就是'运行的时候'。"** 那是**运行期**；本章的"运行时"多指**运行时系统 / 库**（见上文注解）。
- **"只有 Java / Python 有运行时，C / C++ 没有。"** C 也有运行时（CRT），只是很薄。
- **"JIT 一定比 AOT 快（或慢）。"** 各有所长：AOT 启动快，JIT 能用运行时信息做更激进的优化——取决于场景。
- **"有 GC 就一定有虚拟机。"** 不一定：Go 有 GC，却编成原生码、没有字节码虚拟机。**运行时 ≠ 虚拟机。**
- **"运行时开销都是坏事。"** 它换来的是内存自动管理、安全与跨平台，多数场景利大于弊。

## 8. 思考题

1. 为什么 JIT 能"既启动快、又跑得快"？相比 AOT，它在运行时多知道了哪些信息，从而能做 AOT 做不到的优化？
2. Go 有 GC，却没有字节码虚拟机。这件事说明"运行时"和"虚拟机"是什么关系？
3. 用"运行时厚薄"解释：同一个 CPU 密集循环，为什么 C++ 通常比 Python 快很多，而 Java 跑久了却能接近 C++？

## 9. 本章小结

**一句话总结**：运行时（运行时系统）是程序运行时语言在背后提供的一整套支持——内存（GC）、异常、线程、反射、JIT；它可能是虚拟机、是链接进程序的库、或引擎的一部分。运行时越"厚"越省心越安全、越"薄"越快越可控；而 JIT 用"边跑边编热点"兼得了解释的启动快与编译的运行快。
